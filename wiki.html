01　版本与功能

组件版本安装位置
CapeBridgeProxy1.0BC/plugins
CapeBridgeBackend1.0每个子服/plugins
CapeBridgeWebAdmin1.0BC/plugins

支持静态 / 动态披风、试穿、网页贴图管理、隐藏橱柜款式、跨服资源包会话、原版/SR 披风恢复与高版本 scale 跟随。主要验证客户端为 1.20.1 和 1.21.11；其他版本及 XCord 等代理分支需自行验证。

本次已移除全部 /rdp 指令和 Windows 系统操作。插件运行不再因这些功能要求 Windows 管理员权限。披风转向和弯折算法没有在本版重新调整。

不同客户端、网络及帧率下的高速转身效果需实机验收；兼容层存在不等于每种组合均已测试。

02　安装与资源包

  1. 正常停止 BC 和子服，备份现有插件及数据。
  2. BC 安装 Proxy 和 WebAdmin；每个子服安装 Backend 与兼容的 PacketEvents（本项目依赖 2.14.0）。每个组件只留一份 JAR。
  3. 先启动 BC，复制自动生成的 CapeBridgeProxy/config.yml 中 sync-secret，填入所有子服的 CapeBridgeBackend/config.yml。
  4. 配置玩家实际可下载的资源包地址，正常重启后进入子服执行 /cape。
不要公开同步密钥或整个运行文件夹。本插件本身不需要数据库；SR 等第三方插件是否需要数据库由其自身配置决定。

资源包地址

BC 默认仅监听 127.0.0.1:25680，路由为 /capes.zip。公网玩家无法通过自己的回环地址访问服务器；请设置可达的下载域名/IP、相应监听与网络规则。内网路由可通过 resource-pack.local-routing 配置。

资源包始终可选。拒绝或失败不踢人；未加载者不会看到插件披风。跨服是否需要重新下载由会话与资源包内容版本决定，不以切换子服直接重置。

03　权限与常用命令

佩戴授权与管理权限在 BC 检查。子服 OP 不自动获得 BC 管理权限。以下权限管理命令适用于 BC 已安装 LuckPerms 的情况。

节点作用
capebridge.use子服菜单，默认允许
capebridge.cape.<id>单款佩戴权限
capebridge.cape.all佩戴所有款式，并在橱柜看到隐藏款
capebridge.adminBC 管理与 Web 登录码；子服同名权限另管本地诊断

cape.all 不是插件实际读取的节点。请使用完整的 capebridge.cape.all。

命令用途
/cape打开披风橱柜
/dynamiccape / /dcape打开动态披风橱柜
/cape pack重新尝试加载资源包
/cape ver查询组件版本
bcape listBC 查询已加载披风 ID
bcape reload读取配置与资源，重建资源包
bcape set 玩家名 ID管理员装备，须先授予对应佩戴权限
bcape clear 玩家名卸下插件披风
capewebBC 获取网页网址与一次性登录码

控制台命令不带斜杠，游戏中执行时加斜杠。按玩家名设置时玩家须在线；离线玩家请用 UUID。

04　查询 ID / 发放隐藏款

无需登录网页。在 BC 控制台执行：

列出实际已加载披风
bcape list

也可查看 BC 的 plugins/CapeBridgeProxy/capes.yml：capes: 下的一级键就是 ID，披风显示名称与模型编号不是 ID。若配置里有 ID 但列表没有，请检查启用状态与缺失/无效图片的日志。

隐藏款 wardrobe-visible: false 仅影响橱柜。先给单款权限，再由管理员装备，玩家无需拥有全部披风权限。单款授权不使隐藏款在橱柜出现；卸下后需管理员重新装备，或更改可见性。

命令生成器

只在浏览器本地生成文字，不连接服务器，不自动执行。请输入上方查询到的真实 ID。

输入玩家名和 ID 后生成
lpb user Steve permission set capebridge.cape.example true
bcape set Steve example

初始 example 是占位示例。卸下用 bcape clear 玩家名；卸下不自动撤销佩戴权限。

05　网页与登录排查

在 BC 控制台执行 capeweb，或由具有 BC capebridge.admin 权限的玩家执行 /capeweb。游戏消息提供可点击地址和可复制登录码。

默认地址 http://127.0.0.1:27780/ 仅在服务器本机打开。登录码有效期 3 分钟，成功使用一次即失效；会话有效期 1 小时，BC 重启后原登录码与会话均失效。

执行 /capeweb 提示无权限

在 BC 的 LuckPerms 给管理者 capebridge.admin。全部披风权限不包含管理权限，子服 OP 也不能替代 BC 授权。

lpb user 管理员玩家名 permission set capebridge.admin true
网页完全打不开

先检查 BC 日志里 WebAdmin 是否启用、端口是否被占用。远程服务器上的 127.0.0.1 指向服务器本身；你电脑上的同一地址指向你的电脑。远程管理可在服务器桌面打开，或使用隧道/HTTPS 反向代理。

能打开网页，但是登录码无效或 403

重新执行 capeweb 后立即使用新码。核对浏览器地址与 public-base-url，协议、主机、端口必须匹配；不要混用 localhost 与 127.0.0.1。每个来源一分钟内连续 5 次失败会触发限流，稍后再试。

反向代理配置示例

下例域名仅作示例，须替换成你控制的实际域名，并配置相应反向代理。使用独立域名根路径，不支持子路径前缀。保留浏览器请求的 Origin，代理转发的 Host 应与公开站点匹配。

bind: 127.0.0.1
port: 27780
public-base-url: 'https://cape-admin.example.com'
backup-limit: 20

修改 WebAdmin 配置后正常重启 BC。不要为了排查登录而关闭来源校验。

06　贴图与动态披风

输入规则
原版 PNG2:1 展开图，64–512 像素宽
单体 PNG5:8 比例，由导入器转换
GIF最多 10 MiB / 512 源帧，输出最多 64 帧；转换为原生 PNG 动画
动画时长Minecraft 50ms tick，无法保留所有 GIF 原始帧率

在网页上传、替换贴图，或将 PNG 放进 BC 的 plugins/CapeBridgeProxy/capes/ 并执行 bcape reload。ID 使用小写字母、数字、下划线、短横线，长度 1–32。

“在披风橱柜中显示”开关仅改变橱柜可见性，不授予佩戴权限，也不取消既有佩戴。动态款在独立动态菜单中显示。删除或替换前自行备份原图。

07　原版 / SR 披风自动切换

  • 已加载资源包，未装备：显示账号原有或 SR 提供的披风。
  • 插件披风实际显示：只对能看到它的观看者隐藏原版披风，避免重叠。
  • 卸下插件披风：恢复玩家原有的披风显示偏好。
  • 试穿：本人看到试穿款；其他玩家的原版/已装备披风显示不受试穿取代。
  • 拒绝或加载失败：不踢出玩家，保留原版/SR 披风。
需要原账号或 SR 确实提供 CAPE 纹理，并且玩家客户端开启披风显示。本插件不创造正版披风权益。旧配置键 hide-native-cape-when-loaded 不再触发“加载即隐藏”。

08　文本与设置

位置内容
BC / CapeBridgeProxy/messages.yml代理管理命令、聊天与日志文字
BC / CapeBridgeWebAdmin/messages.yml网页与登录提示
子服 / CapeBridgeBackend/gui.yml菜单标题、按钮与描述
子服 / CapeBridgeBackend/messages.yml子服聊天与诊断文字

支持的颜色与占位符以默认文件为准。修改后通过对应的文本重载命令生效，或正常重启。渲染与高版本补偿参数在 Backend/config.yml；修改前保留副本，不要一次调整多个参数后直接用于正式服。

09　构建与更新

安装 JDK 21、Maven 3.9+，在源码根目录运行：

编译并运行测试
mvn clean verify

Windows 可执行 ./build.ps1 -Clean；Linux/macOS 使用 sh build.sh。离线构建要求依赖已缓存。原版参考回归语料已随测试资源提供，不需要额外的 collector 目录。文件链接测试需要相应权限或 Windows 开发者模式，HTTP 测试需要允许回环连接；这不等于运行插件需要管理员权限。

proxy/target/capebridge-proxy-1.0.jar
backend/target/capebridge-backend-1.0.jar
web-admin/target/capebridge-web-admin-1.0.jar

更新时正常停服，仅替换对应组件并保留现有配置、贴图和玩家数据，正常重启后用 /cape ver 检查。不要保留多个版本或使用热加载器。

本版没有系统管理指令。旧服务器数据目录中的 system-rdp 不会被新版执行，不要将其中的旧操作记录发布到源码仓库。移除代码不会回滚此前修改的 Windows 设置。
